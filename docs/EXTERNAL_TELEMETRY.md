# External telemetry frames

The public GUI can display images generated by your own monitoring or
automation tool. The driver deliberately treats this integration as data, not
code: it reads PNG files from a selected folder and never imports or executes
the producer.

## Folder formats

Use either of these formats:

```text
frames/
└── triptych.png        1920 × 180, left + centre + right
```

or:

```text
frames/
├── panel-0.png         left visual position, 640 × 180
├── panel-1.png         centre visual position, 640 × 180
└── panel-2.png         right visual position, 640 × 180
```

Images with other dimensions are resized to the required output. The GUI's
physical panel mapping is applied after the visual positions are loaded.

## Safe updates

Write a temporary file in the same folder and rename it over the live file.
That keeps the renderer from observing a partially written PNG:

```python
from pathlib import Path
from PIL import Image, ImageDraw

folder = Path.home() / ".local/share/zc360-frames"
folder.mkdir(parents=True, exist_ok=True)

image = Image.new("RGB", (1920, 180), "#080c13")
draw = ImageDraw.Draw(image)
draw.text((30, 30), "Telemetry from my own collector", fill="white")

temporary = folder / ".triptych.next.png"
image.save(temporary)
temporary.replace(folder / "triptych.png")
```

In **ZC-360 Control**, choose **External telemetry frames**, browse to this
folder, choose a polling interval, and select **Apply display mode**. The
producer and renderer can be restarted independently, and neither one should
claim the USB interfaces.
